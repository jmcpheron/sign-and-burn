# 2026-10-10: finishing a transaction proposed in Safe{Wallet}

## The ask

The second Safe (`0x1EF7…6D82`) took a third owner, an ordinary wallet (`0x1289…F2DA`), and is now
2 of 3. From that wallet, in Safe{Wallet} (app.safe.global), Jason proposed a USDC send. The page should
be able to take the pending transaction on.

## What was there

Read on 2026-10-10 (the chain with `cast`; Safe's transaction service with `curl`, from the development
machine, not the page): owners `0x1289…F2DA` and both seats, threshold 2, nonce 6. One transaction
waiting, at nonce 6: 0.67 USDC (`transfer`) to `0x1289…F2DA`, no gas refund, Safe transaction hash
`0xf08f0f9f…760d22`, with one confirmation: `0x1289…F2DA`'s off-chain signature (type EOA). Safe{Wallet}
keeps it on its service, not on chain, so the page, which reads votes from the chain (`approvedHashes`),
couldn't see it.

## What changed

- **"A transaction from Safe{Wallet}"**, on the wallet page's Send card. The page doesn't fetch from
  Safe's service: AGENTS.md's rule 6 lets it reach its folder and the RPC, nothing else. So it links to
  the service's list of this Safe's waiting transactions, and you paste what it shows.
- **The pasted text is untrusted.** `pay.fromSafeWallet` checks every field's shape, and refuses gas
  refunds, which the page doesn't make or run. The page takes the transaction at the Safe's nonce. The
  console works out its hash from the fields, and the page refuses it unless that is the hash
  Safe{Wallet} gave. Each signature must recover (`chain.signerOf`: EIP-712's v 27/28, or eth_sign's v
  31/32) to the owner it names, and that owner must be one of the Safe's; any other is left out, and
  the page says so.
- **Its signatures count as votes** ("signed in Safe{Wallet}"). A seat's press, or a wallet's "Run it",
  carries them into `execTransaction`: `chain.execData` puts each owner's signature beside the
  pre-approved votes, all in ascending order of owner, as Safe requires. An owner with an on-chain vote
  needs no signature.
- Fold-outs on the wallet page ("Add a token", this one, the address book's paste) stay open across a
  redraw. Before, a refusal closed them, with what was pasted.

The console and the contracts are unchanged. Nothing is signed in a new way: the page only checks and
passes on signatures other wallets made.

## What was checked, and how

- The real one, offline: the service's JSON for `0x1EF7…6D82` through `pay.fromSafeWallet`, the console's
  review on CPython, and `chain.signerOf`. The console reads "Send 0.67 USDC", level ok, works out
  `0xf08f0f9f…760d22` (Safe{Wallet}'s hash) with check code `29760d22`, and the signature recovers to
  `0x1289…F2DA`. One seat's press should run it; not done yet.
- `npm test`: both kinds of signature recover to their signer, another hash doesn't, a pre-approved
  one isn't read as a signature; a signature beside a vote, in owner order; the service's JSON reads,
  and eight bad ones are refused.
- `npm run e2e`: all 150 checks pass. New: a Safe{Wallet}-style transaction with the wallet's
  off-chain signature (Anvil's test key), and a forged one naming the second seat. A tampered hash is
  refused; the real one imports with 1 of 2, the forged signature left out; the first seat's press
  runs it.

## Not done

- The other way round: whether Safe{Wallet} counts a seat's on-chain vote (the Safe's `ApproveHash`
  event) as a confirmation, so its own "Execute" would work. Not tried.
