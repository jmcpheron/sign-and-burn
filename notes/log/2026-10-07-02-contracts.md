# 2026-10-07, late: the contracts (M1)

## The failing vector test was the test's own bug

```solidity
bytes32[67] memory bad = sig;   // not a copy: bad and sig are the same memory
bad[5] = bytes32(0);            // so this zeroed sig[5] too
```

The next check compared the test's own signature with `sig`, and failed at chain 5. The contract was
right. The test now copies element by element. 16 tests passed; one approval measured 573,599 gas
against mocks.

## Base Sepolia's RPC, asked directly

- **CORS:** `https://sepolia.base.org` answers browsers, with `access-control-allow-origin` set to the
  asking origin. So the page can call it directly.
- **Logs:** `eth_getLogs` is "limited to a 500 range": 500 blocks, about 17 minutes. Events can't be the
  page's memory.

So the contracts got two indexes: `SeatFactory.seatsOf(signer)`, a passkey's seats; and
`Seat.approvedIn(n)`, the block each approval landed in, so one log query of one block finds it.

## Against the real contracts

The kickoff planned an Anvil fork of Base Sepolia. Instead, a background agent fetched the runtime
bytecode of the 9 contracts the seat relies on from Base Sepolia (block 47,836,700) into
`tools/chain/code.json`, and the tests put each at its own address with `vm.etch`. CI then needs no RPC;
a weekly job checks the bytecode against the chain.

Found along the way:
- **Base Sepolia and Anvil 1.8.3 both have the P-256 precompile at `0x100`.** A real signature returned
  1; a changed one, nothing. So the local chain checks passkeys as Base Sepolia does.
- **Multicall3 hides the seat's error** behind "Multicall3: call failed". The page asks the seat
  directly when it wants the reason.
- **An approval lands even when the Safe transaction can't run** (`allowFailure` on
  `execTransaction`): the key burns, the Safe's nonce stays, and the vote stays for anyone to run it.
- **The SeatFactory, through the CREATE2 deployer with salt 0, is at
  `0x0a6514135d34dfd19c3f1a636f3e952caeba3871` on every chain.** The build is deterministic
  (`bytecode_hash = "none"`, pinned solc): two clean builds gave the same bytes.

22 tests passed, on Cancun and on Osaka.

## A label fixed later

The fallback verifier at `0xc2b7…4De4` was first labelled "FCL" in `code.json`. It is Daimo's
p256-verifier (MIT), a different implementation. Renamed `DaimoP256Verifier` everywhere, and NOTICE
corrected; the tests still pass.
