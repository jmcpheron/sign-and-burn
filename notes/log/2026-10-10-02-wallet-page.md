# 2026-10-10: a wallet page, and a second owner

## The ask

A separate page that is just a wallet, showing the sign-and-burn process, with multisig controls.
Someone trying the passkey can add their regular Ethereum wallet as another owner of the Safe, say
1 of 2. That gives up the seat's protection against broken curves, since the wallet's public key is
usually public already. But it is a backup, a way to get used to a multisig, and a way to move keys
over to sign and burn one at a time.

## What changed

- **`site/wallet.html`**, served at `/wallet.html`. The Safe's balance, a send form, its owners,
  and the seat's approvals. Making a passkey and building the Safe stay on the main page; this page
  sends you there if you haven't.
- **The same storage as the main page**: the passkey, `sab.home` and the console's ledger. So the
  guardrail is the same one. Whichever page signs with key `n`, the other only sends that approval
  again.
- **Owner changes**: add an owner (with a button for the wallet in this browser), remove one,
  change the threshold. Each is a Safe transaction to the Safe itself. The console marks it red,
  as it always has, and holding waits for "I read the red page". The page doesn't offer to remove
  the seat.
- **Two kinds of vote.** The seat votes with one press, as before. A wallet that is an owner votes
  with its own curve key: `approveHash`, or `execTransaction` sent by itself when its vote makes
  enough. That goes straight to the Safe, not through Multicall3, because Safe counts the sender's
  own vote. Before this, the wallet only ever paid gas. The page says so where the button is, and
  `chain.mjs`'s header says so too.
- **A seat's press carries the other votes.** `approveCalls(a, tx, others)` adds the votes the Safe
  already holds to the `execTransaction` after `seat.approve`, in ascending order of owner, so a
  2 of 2 runs in the same block when the wallet voted first. With no others it sends the same bytes
  as before.
- **The verdict.** For a Safe with one seat, the owners card says whether the other owners reach the
  threshold without the seat. If they do, that is the backup for a lost passkey, and also the way
  around the seat. With one seat you get one or the other, never both. It counts only this
  browser's seat as a seat. Each ordinary owner says whether its public key is on chain, read from
  its transaction count: an address that has sent a transaction has shown its key.
- **A transaction waiting for votes** is kept in `sab.proposal` until it runs. A transaction key `n`
  signed and hasn't landed belongs to the ledger, and the card offers only that one, with no Reject.
  If another owner runs something else at that Safe nonce, the card says the approval was overtaken.
  It still sends only that approval: it lands, runs nothing, and the seat moves on to the next key.
- **Shared code.** `src/approve.mjs` is the press for both pages, moved out of `main.mjs` with its
  messages unchanged. `src/ui.mjs` holds the small parts both pages draw with. `src/app.mjs` is
  the one script both pages load, so `docs/` still has one `app.js`. esbuild's code splitting made
  ten chunk files out of viem's lazy imports, so the build doesn't split.

The console is unchanged, so its fingerprint is too. The contracts are unchanged.

## What was checked, and how

- `npm test`: votes in ascending order of owner; a press with no other votes sends the seat's vote
  alone, as before; add, remove (the owner before it, or the sentinel) and threshold calls; removing
  an address that isn't an owner is refused.
- `npm run e2e`, with Foundry 1.8.3 and Chromium, against the local chain: all 103 checks pass,
  three runs in a row after the last fix. The wallet page's checks are item 16 in
  [testing/page.md](../testing/page.md).
- `npm run build` twice: the same bytes. `docs/` rebuilt; the console fingerprint is unchanged.
- The one-time keys (Python and JavaScript), the console on CPython and MicroPython, and
  `node tools/fingerprint.mjs --check`. The contracts weren't touched, and their tests weren't run.

Not checked: any of it on Base Sepolia, by hand, with a real browser wallet as an owner. A hardware
wallet as an owner. A Safe with more than one seat.

## Found along the way

- The e2e's nonce arithmetic was wrong at first: the threshold change is a Safe transaction too, so it
  uses up a nonce.
- The wallet page scrolled sideways at phone width while a transaction was open. Its columns had no
  `minmax(0, 1fr)`, so they grew to fit the Safe transaction hash, and the hash didn't wrap. The e2e
  checked the width only after the card had closed. It now checks with the card open, and names any
  element past the edge. The hash wraps on both pages now.
- The main page, an old race: a link pasted into "Pay for a request" while the page was still starting
  was opened twice. Start-up found the link in the address bar and opened it again, so for a moment
  the screen went back to "Working out what the link builds…". The e2e caught that moment once in
  four runs. Start-up now leaves an open review alone and only redraws it, with the wallet it has
  reconnected since. Without that redraw the "Send it" button never showed: the e2e caught that too.
- Twice in about ten runs, the main page lost the recipient the e2e typed just after the wallet
  switched accounts twice, and the press went to the wallet's own address. Each switch reads the
  chain, then redraws. The first switch's redraw could land after the second's, while the e2e was
  typing: Playwright selects the field and types in two steps, and the redraw replaced the field in
  between. A person typing then would lose it too. A switch that a later one has replaced no longer
  redraws, on either page. Logging every change to the recipient hid the race (four runs, all
  passing), so the cause is read from the code, and the check is that it hasn't come back.
- The guardrail and other owners: with an ordinary owner who can act alone, the Safe's nonce can move
  under a signed, unsent approval. Key `n` has signed it, so the console sends only that approval,
  ever. The page sends it rather than leave the seat stuck at key `n`, and says it runs nothing. That is research.md's
  "standing vote", seen from the other side.
